### Phase 2 diagnosis: ECONNREFUSED is NOT a code defect

`ECONNREFUSED 127.0.0.1:8000` means exactly one thing: **nothing was listening on 8000.**
Django was never started in that terminal (the earlier `npm run dev` ran from the repo
root, failed on a missing package.json, and Django was stopped). Django does not crash:
it starts clean and serves `/api/health` with 200. There is no traceback to find because
there is no failure. The real, legitimate improvement is to make the binding address
unambiguous so this confusion cannot recur.

### Security posture (good, verified)

- No CORS package — correct, the Vite proxy keeps everything same-origin.
- `ALLOWED_HOSTS = localhost,127.0.0.1,testserver` default; `CSRF_TRUSTED_ORIGINS` env-driven.
- `SESSION_COOKIE_HTTPONLY=True`, `SAMESITE=Lax`, `SECURE=not DEBUG`; `CSRF_COOKIE_HTTPONLY=False` (correct — the SPA must read it).
- `X_FRAME_OPTIONS=DENY`, `SECURE_CONTENT_TYPE_NOSNIFF=True`.
- Passwords: 4 Django validators, min length 8.
- `.env` gitignored; `.gitignore` covers `.env`, `db.sqlite3`, `dist/`, `node_modules/`.
- No secrets, no `localStorage` token storage, no hardcoded credentials in `frontend/src`.
- Money crosses the API as a decimal **string** (`COERCE_DECIMAL_TO_STRING=True`), pinned deliberately.

### Maintainability findings

1. **No version control.** The entire 46k-line project is unversioned. This is the largest
   reliability risk in the repository — no diffs, no rollback, no blame, no branch.
2. 273 API patterns for a single-tenant app includes DRF's `?format=` duplicate routes
   (half the 273). Harmless, but no `format_suffix_patterns` needed.
3. `pages/*/api.ts` module layers (2,822 lines total) sit above the central `src/api/client.ts`
   (576 lines). This is a deliberate two-layer seam, not duplication — the central client
   owns transport/CSRF/errors, module layers own domain shapes. **Keep it.** Do not collapse.
4. Largest components are large but coherent: `PaymentsPage.tsx` 1118, `AttendancePage.tsx` 1045,
   `PayrollPage.tsx` 936. Refactor only if a task requires touching them.

### Task A2: Make the dev workflow unambiguous
**Objective:** the port story cannot be misread again.
**Files:** Modify `Makefile` (`run` target)

**Step 1 — bind explicitly to loopback** (keep 0.0.0.0 available as a separate target for LAN):
```make
run:
	cd backend && ../$(PY) manage.py runserver 127.0.0.1:8000

run-lan:
	cd backend && ../$(PY) manage.py runserver 0.0.0.0:8000
```
Rationale: `0.0.0.0` is a *bind* address; `127.0.0.1` is a *destination*. Binding to
loopback makes it impossible to browse to a host Django will reject. Do NOT add `0.0.0.0`
to `ALLOWED_HOSTS`.

**Step 2 — add a preflight target**
```make
dev-check:
	@curl -s -o /dev/null -w 'Django  :8000 -> %{http_code}\n' http://127.0.0.1:8000/api/health || echo 'Django  :8000 -> DOWN (run: make run)'
	@curl -s -o /dev/null -w 'Vite    :5173 -> %{http_code}\n' http://localhost:5173/ || echo 'Vite    :5173 -> DOWN (run: make frontend-dev)'
```

**Step 3 — verify**
```bash
cd /Users/temurbek/uchebniycrm && make run    # terminal 1
make dev-check                                # terminal 2
```
Expected: `Django :8000 -> 200` then `Vite :5173 -> DOWN` before Vite starts.
